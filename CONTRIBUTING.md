# Contributing

Contributions are welcome.

1. Create a focused branch from `main`.
2. Keep Codex-only and credential-safety constraints intact.
3. Run the repository CI checks before opening a pull request.
4. Do not commit credentials, tokens, private logs, or user-specific paths.
5. Update documentation and tests when behavior changes.

Release changes should use a new semantic version and a new tag. Published tags and release assets should be treated as immutable except for explicitly approved migration repairs.
